# 도구 설명은 프롬프트다 — 모델이 실제로 읽는 입력을 직접 만들어 확인한 실측 랩

도구를 쓰라고 명령하면 모델은 도구 설명도 함께 읽을까요? 이 질문을 실측으로 확인했습니다. 모델은 Ollama의 qwen3.5:2b이고, 온도 0과 reasoning=False로 실행했습니다. 도구는 colab-mcp의 open_colab_browser_connection을 썼고, 실습 파일은 class\show_injection.py입니다.

> 근거: 2. 2번 노드 실측 랩 — 도구 설명이 모델 입력에 들어가는가

코드 1에서는 모델에 "구글 코랩을 브라우저로 연결해 줘"를 보냈습니다. 모델은 open_colab_browser_connection을 호출했고, 읽은 토큰 수(prompt_eval_count)는 289였습니다. 하지만 이 숫자만으로는 모델이 어떤 글을 읽었는지 알 수 없습니다.

> 근거: 세 코드가 각각 확인하는 것

그래서 코드 2에서는 모델 파일(GGUF)에서 채팅 템플릿을 꺼내, 모델이 읽었을 입력 글을 직접 만들어 출력했습니다. system 칸의 <tools> 안에 도구 설명이 들어 있었고, 그 아래 user 칸에 질문이 있었습니다.

> 근거: 세 코드가 각각 확인하는 것

코드 3에서는 코드 2가 만든 글을 그대로(raw) 모델에 보내 토큰 수를 쟀습니다. 결과는 288이었습니다. 코드 1의 289와 1토큰 차이인데, 노드 설명에 따르면 시작 토큰과 빈 생각 블록을 처리하는 방식의 차이입니다. 따라서 코드 2의 글이 실제로 모델이 읽은 입력이라고 볼 수 있습니다.

> 근거: 세 코드가 각각 확인하는 것

노드에는 코드 1만 파일 이름이 적혀 있었습니다. 하지만 코드 2는 코드 1의 tools와 convert_to_openai_tool을 쓰고, 코드 3은 코드 2의 rendered를 써서 각각 따로는 실행되지 않습니다. 또 하나뿐인 실행 명령에 세 코드에 필요한 패키지가 모두 들어 있었습니다. 그래서 코드 1의 main() 안에 코드 2와 3을 이어 붙였고, 노드 코드에서는 colab-mcp 경로 하나만 바꿨습니다.
